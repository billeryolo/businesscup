Один контракт для фронтенда и бэкенда

Один разработчик делает бэкенд и проверяет его на простой заглушке. Второй делает весь фронтенд на моках. Оба опираются на один файл src/lib/api/contract.ts: в нём каждый маршрут, каждый эндпоинт и форма каждого запроса и ответа. В конце меняется один флаг, и фронтенд начинает ходить в настоящий бэкенд.

Правила контракта

Считает только бэкендФронтенд отправляет сырые данные: услышанные слова, ответы, отметки родителя. Слова в минуту, точность, вердикт и паттерны возвращает бэкенд. Так результат нельзя подделать, а логика подсчёта живёт в одном месте.
Фронтенд не трогает SupabaseСейчас save.ts и dashboard/page.tsx ходят в базу напрямую. Это переезжает в эндпоинты: submitReading, claimCheck, progress.
ФорматJSON, поля в camelCase, даты в ISO 8601 с часовым поясом, id в формате UUID. Пустой ответ — 204 без тела. Сессия хранится в cookie Supabase, токены во фронтенде не нужны.
ОшибкиВсегда { error: { code, message } }. Коды: VALIDATION 400, UNAUTHENTICATED 401, FORBIDDEN 403, NOT_FOUND 404, CHILD_LIMIT 409, TOO_SHORT 422, RATE_LIMITED 429, INTERNAL 500.
Класс ребёнкаgrade от −1 до 4: −1 — Pre-K, 0 — подготовительный класс (K), 1–4 — школа. Архетип назначает бэкенд: −1 → explorer, 0–1 → builder, 2–4 → fluent.
Без входа тоже работаетБесплатную проверку можно пройти без аккаунта. Бэкенд вернёт claimToken, а после входа фронтенд отправит его в /api/checks/claim и результат сохранится.
ПриватностьАудио не хранится и никуда не уходит. Имя ребёнка не отправляется в ИИ: модель видит заглушку {{child}}, как сейчас.
Как менять контрактТолько PR, который меняет contract.ts и mocks.ts вместе, с новой версией CONTRACT_VERSION и одобрением обоих. npm test должен проходить.

Формы данных

Главные модели

Сокращённая запись. Полные схемы с ограничениями лежат в contract.ts, типы берутся оттуда через z.infer.

Child

{
  id: uuid
  firstName: string        // 1–40 символов
  grade: -1..4             // -1 Pre-K, 0 K
  archetype: "explorer" | "builder" | "fluent"
  domains: Domain[]        // ["reading","math"] для fluent
  sessionMinutes: 5 | 10 | 15
  stars: int, streakDays: int
  createdAt: ISO
}

CheckResult

{
  id: uuid | null          // null, пока не сохранено
  childId: uuid | null
  domain: "letters" | "reading" | "numbers" | "math"
  measure: "wcpm" | "lettersPerMinute" | "factsPerMinute"
  value: int               // главное число
  accuracy: 0..1
  benchmark: { median, p25, season, source } | null
  band: string | null      // "25th–50th"
  verdict: "onTrack" | "practice" | "talkToTeacher"
  patterns: Pattern[]
  details: reading | math | letters   // по полю kind
  claimToken: string | null
  summary: ParentSummary | null
}

DomainProgress (внутри Progress)

{
  domain: Domain
  status: "notStarted" | Verdict
  measure: ... | null
  points: { takenAt, value }[]   // старые сначала
  benchmark: Benchmark | null    // линия нормы
  weeklyGrowth: number | null    // пунктир «в темпе»
  lastCheckId: uuid | null
  nextCheckDue: ISO | null
}

TodaySession

{
  childId: uuid
  minutes: int
  activities: {
    kind: "letterTap" | "mathFacts" | "story" | ...
    domain, skillId: "math.add20"
    label: "Adding within 20"
    minutes: number
    params: { family: "add20", purpose: "practice" }
  }[]
  dueCheck: { domain, kind } | null
}

ReadingSubmission

{
  childId: uuid | null, childName: string
  grade: -1..4, passageId: string
  mode: "live" | "manual" | "demo"
  seconds: 0..60
  spoken: { word, t? }[]       // от распознавания речи
  lastWordIndex?: int          // ручной режим
  parentMarks: int[]           // слова, отмеченные родителем
  consent: boolean             // true для mode "live"
}

{
